Ask what happens if the new rule fires ten thousand times

A rule is also an action. Before it ships, somebody should say out loud what breaks if it matches far more often than expected.

A detection is not only a query. It is the first link in a chain of things that happen automatically.

Downstream there is usually a ticket, often a page, sometimes an enrichment job that queries three other systems, and increasingly an automated response that isolates a host or disables an account. Each of those is fine at the expected rate and has an unpleasant failure mode at a hundred times the expected rate.

The rule was tested on data chosen because it contained the behaviour. That tells you the logic matches. It tells you nothing about how often the logic matches in an estate you did not curate.

So the question before enabling anything is not whether the rule is correct. It is what happens if it is correct far more often than you think.

Two guards cover most of it. Run the rule in a mode that records matches without acting, for long enough to see a normal week including the batch jobs that run at month end. And put a ceiling on what any single rule can do per hour, so a surprise costs you a backlog rather than an outage.

For the next rule you enable, write down the expected daily match count first. Then compare it to the first week.

CHECK YOURSELF

A new rule is ready and tests cleanly on sample data. Before enabling it in production, which question matters most?

SHOW THE ANSWER

What happens downstream if it matches ten thousand times in an hour

Why. A detection is wired into things that act: paging, ticket creation, enrichment jobs, sometimes automatic containment. Those consequences scale with match volume, and sample data tells you nothing about volume because it was chosen to contain the behaviour. The other three are all real parts of shipping a rule and none of them can page somebody at four in the morning or quarantine a fleet. Naming, mapping and duplication are tidiness problems; match volume is an availability problem.
