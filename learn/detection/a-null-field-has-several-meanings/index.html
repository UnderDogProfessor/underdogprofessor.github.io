An empty field has more than one meaning

Not collected, collected but empty, and collected but unparsed all look identical in a query. Only one of them means the thing did not happen.

A field is empty. That tells you less than it appears to.

There are at least three reasons a value is missing, and a query returns the same thing for all of them.

The field was never collected on that host, because the policy differs, the agent is older, or the feature is licensed separately. The field was collected and is genuinely empty, because the thing it describes did not happen. Or the field was collected, arrived, and the parser failed on it, so the value went nowhere.

Only the middle one means what people assume.

This matters most in exclusions. Writing a condition that skips empty values feels like tidying. It silently removes every host with a collection gap from the rule’s population, and those hosts are rarely a random sample. They tend to be the old and unmanaged ones.

The fix is not clever. Separate the concepts. Track per source and per field whether collection is expected, so absence can be compared against a baseline rather than guessed at. Then an empty value means something.

Take one exclusion in a rule you own that skips blank values. Count how many events it removes per day, and how many distinct hosts those come from.

CHECK YOURSELF

A rule excludes events where the command line field is empty, on the reasoning that there is nothing to match. What does that exclusion quietly remove?

SHOW THE ANSWER

Every event where the field was never collected or failed to parse, whatever the process did

Why. The query cannot tell the three cases apart, so the exclusion catches all of them. Processes with no arguments are the harmless case and the one people picture. The dangerous cases are hosts where that field was never collected and events where the parser failed, because both can cover exactly the activity the rule exists to find. The third option is the reasoning that makes this feel safe: it is true that an empty field will not match, and irrelevant, because excluding the event also stops every other condition in the rule from being evaluated against it.
