The window matters as much as the count

Five failures in five minutes fires. The same five failures spread over five hours do not, and nothing tells you the second case happened.

Every counting rule has two numbers. Almost all the attention goes to one of them.

The count gets tuned. Ten failures, then eight because eight felt safer, then back to twelve because eight was noisy. Meanwhile the window sits at whatever it was when somebody wrote the rule, usually five or ten minutes, and nobody revisits it.

The window is what the rule can see. Outside it, events are unrelated by definition, however obviously they belong together to a person looking at them.

So an adversary who waits does not need to evade anything. Spacing attempts past the window is not a technique, it is patience, and it works against every rule that counts inside a fixed period.

The answer is rarely to widen the window on the existing rule, because a count that is sensible over five minutes is meaningless over a day. It is to run both: a tight rule for the fast case, and a separate wider one with its own count, accepting that the wide rule alerts later and is worth having anyway.

Take one counting rule you own. Write down its window. Then ask what the same behaviour looks like at one tenth the rate, and whether anything you run would see it.

CHECK YOURSELF

A rule fires on ten failed logons for one account within five minutes. An adversary spreads ten attempts across a working day instead. What is the most useful change?

SHOW THE ANSWER

Add a second rule over a much longer window with a count tuned for that period

Why. Short and long windows answer different questions and both are worth asking, so the answer is usually another rule rather than a change to this one. Lowering the count inside five minutes makes the fast rule noisier without reaching a pattern that never puts three events in five minutes. Removing the window turns the rule into a lifetime counter that eventually fires for everybody and never resets. Severity governs what happens after a match, and this rule never matches.
