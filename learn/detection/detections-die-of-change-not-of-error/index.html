Most detections die of change

Rules rarely turn out to be wrong. They stop fitting, because the thing they described moved, and nothing in the platform reports a poor fit.

Detections do not usually fail by being wrong. They fail by being outlived.

The rule was accurate when it shipped. Then the software version changed, the field was renamed, the workload moved, the team adopted a different tool, the attacker technique it described stopped being fashionable. The logic is intact and no longer points at anything.

Nothing reports this. A rule that matches nothing looks exactly like a rule guarding a quiet estate, and the platform has no opinion about which it is.

So a rule set ages in one direction. New rules get added because somebody had a reason. Old rules stay because removing them requires an argument nobody has time to make, and because a dormant rule costs nothing visible.

The cost is real anyway. It is the false confidence of a coverage number built from rules that have not matched since March.

Treat a long silence as a question rather than a result. For each quiet rule, one of four things is true: the behaviour stopped, the data moved, the parsing broke, or it never worked. All four are worth knowing and only one is good news.

Sort your rules by last match. Take the ten quietest and find out which of the four they are.

CHECK YOURSELF

You are given time to improve a rule set of two hundred detections. What is usually the highest-value first pass?

SHOW THE ANSWER

Find the rules that have not matched anything in months and establish why

Why. Silent rules are where decay accumulates, and each one resolves into a different action: the behaviour genuinely stopped, the data moved, the parser broke, or the rule never worked. You cannot know which without looking, and every other improvement is built on a set you have not verified. Noise reduction and ATT&CK mapping are both worth doing and both assume the rules still function. Detection-as-code improves how changes are made from here and does nothing about what is already broken.
