Every Kerberos ticket traces back to one key

The krbtgt account's key signs every ticket-granting ticket in the domain, which makes it the one credential a reset cycle cannot be lazy about.

A ticket-granting ticket is proof that the domain controller believes you. What makes it proof is encryption with the key of an account called krbtgt.

That account never logs in. It exists so the domain has one secret that underwrites every ticket it issues.

Which means holding that key is not the same as holding a credential. A password gets you one identity. The krbtgt key lets you construct a ticket for any user, with any group membership you care to claim, that the domain will accept because the signature checks out. The domain controller is not being fooled by a trick. It is doing arithmetic that comes out right.

This is why the account appears in recovery procedures and nowhere else. Rotating it is disruptive enough that nobody does it casually, and important enough that every domain compromise playbook ends with it.

One detail decides whether the rotation works. Active Directory keeps the current key and the previous one, so tickets issued just before a change keep working. Reset once and the compromised key is still the previous key. You have to reset twice, with replication completing in between.

Find out when krbtgt was last reset in your domain. If the answer is never, that is the finding.

CHECK YOURSELF

You are recovering a domain after a confirmed compromise of a domain controller. Why is resetting the krbtgt password twice, rather than once, the standard advice?

SHOW THE ANSWER

Because Active Directory keeps the current and previous key, so one reset leaves the old one still valid

Why. Two key versions are retained deliberately, so that tickets issued moments before a reset keep working and legitimate sessions do not all break at once. That same grace is what an attacker holding the old key relies on. Resetting once invalidates nothing for them. The second reset, after replication has carried the first, retires the compromised key for good, which is why the gap between the two resets matters as much as doing both.
