Your groups are in the token, not the directory

Group membership is stamped into a token or ticket when it is issued, so removing somebody from a group does not take their access away until that token expires.

Removing somebody from a group feels like taking something away. In the directory it is. At the resource, often, nothing has happened yet.

Group membership is resolved at issue time. When a domain controller builds a Kerberos ticket it enumerates the groups and writes them into the ticket, and when an identity provider mints a token it writes the groups in as claims. The file server, the application, the API: they read what they are handed. They do not call back to ask whether it is still true.

Which means a revocation and a ticket lifetime are in a race, and the ticket usually wins the first few hours.

It cuts the other way too, and this is the version that generates helpdesk tickets. You add somebody to a group, they say it has not worked, and they are right until they sign out and back in.

The fix in an incident is not more membership changes. It is ending the sessions, so the next ticket is built from the directory as it is now.

Find out what your ticket and token lifetimes actually are. That number is how long a revocation takes to mean anything, and most people quoting it from memory are quoting the default rather than their own.

CHECK YOURSELF

During an investigation you remove a user from the Finance group at 14:00. They are still reaching the finance file share at 14:20. What is the most likely explanation?

SHOW THE ANSWER

Their existing ticket still carries the old group membership and will until it is reissued

Why. Group membership is evaluated once, when the ticket or token is issued, and travels inside it as a claim. The file server reads the claim it is handed rather than querying the directory on each access, so the removal is real in the directory and invisible at the resource until the ticket is reissued. Replication delay and a second group are both worth ruling out, but neither explains the gap as reliably as a ticket lifetime does. Ending the session, not just the membership, is what actually closes it.
