A complex password can still be a known one

Complexity rules measure which characters a password contains. They cannot tell you whether that exact password already appears in a public breach corpus.

A password policy checks composition. Length, upper case, lower case, a digit, a symbol, perhaps nothing resembling the username. Every one of those is a question about which characters are present.

None of them is a question about whether anybody has used this password before.

Summer2026!Toronto satisfies a strict policy. It is also exactly what a person produces when a rule demands a capital, a digit and a symbol, which means it is close enough to millions of others that a list built from previous breaches reaches it early. The rule did its job. The password is still a poor one.

This is why published guidance moved. The current shape is to drop forced periodic rotation and most composition rules, keep a generous minimum length, and add the check the rules cannot make: compare the chosen password against known-breached and commonly chosen values, and refuse the ones that appear.

That single check removes the passwords an attacker tries first, which is the population that decides the outcome. A spray does not guess at random. It works down a list, and the list is public.

Go and find out whether your directory would reject a password you already know appears in a public corpus. Set one on a test account and watch what happens.

CHECK YOURSELF

Your policy demands 14 characters with mixed case, a digit and a symbol. A user sets Summer2026!Toronto and it is accepted. Why might that still fall to one of the first attempts an attacker makes?

SHOW THE ANSWER

Because the rules measure composition, and say nothing about whether the password is already on a public list

Why. Every composition rule asks a question about characters, and none of them asks whether a human being has chosen this exact string before. Season, year, symbol and place is the shape a person produces when a rule demands a capital, a digit and a symbol, so it sits near the top of lists assembled from previous breaches. Length keeps adding entropy, hashing routines do not discard characters, and the stored form is a hash of exactly what was typed. The missing control is a comparison against known-breached and commonly chosen values at the moment the password is set.
