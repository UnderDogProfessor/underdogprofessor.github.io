Not every account is in the directory

Directory policy governs directory accounts. Every host also carries local accounts of its own, which that policy never reaches.

Your password policy, your multifactor requirement, your conditional access rules and your lockout threshold all live in the directory. They apply to accounts the directory knows about.

Every Windows and Linux host also carries accounts of its own. A local administrator, a root account, whatever an installer created. These exist whether or not the machine is joined to anything, and the directory has no say over them.

That gap is where a great deal of lateral movement lives. If a build image sets the same local administrator password on every workstation, that password is one credential for every workstation. Reading it off one machine reads it off all of them, and no amount of directory policy changes that.

The point is not that local accounts are a mistake. A host needs a way to be administered when the directory is unreachable, which is precisely the situation during an incident, so removing them is not the answer.

The point is that they are governed somewhere else, and most inventories never look there. So the control has to be local as well: a different password on every host, rotated on a schedule by something other than a person, with the current value retrievable and logged when it is read.

Go and compare the local administrator password on two machines you pick at random. You will learn something either way.

CHECK YOURSELF

Your organization enforces multifactor authentication and a rotation schedule through the directory. An attacker reaches local administrator on one workstation and finds the same local password set on every machine in the build. Which of your controls stopped applying?

SHOW THE ANSWER

All of them, because directory policy governs directory accounts and this is not one

Why. Joining a host to a domain does not place its local accounts under domain policy. They remain objects of that machine's own account database, so the multifactor requirement, the rotation schedule, the lockout threshold and any conditional access rule simply have no subject to act on. Local accounts can have a lockout policy, set locally, which is a different thing from inheriting yours. The remedy is local too: a unique password per host, rotated automatically, with the current value held somewhere auditable.
