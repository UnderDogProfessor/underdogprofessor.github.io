The refresh token is the one worth stealing

OAuth issues a short-lived access token and a long-lived refresh token. The second one is standing access, and only the authorization server can end it.

OAuth hands out two tokens, and people guard the wrong one.

The access token is short-lived. Fifteen minutes, an hour, somewhere in that range. It travels with every API call, so it turns up in proxy logs, in error reports, in traces. It also stops working soon.

The refresh token is the other one. Its entire job is to obtain new access tokens without making the user log in again, so it has to last. Days, often weeks: Microsoft Entra ID defaults to 90 days for most clients.

Take an access token and you have a short window. Take a refresh token and you have an authentication method.

That asymmetry is why containment has to reach the authorization server, which is the only place a refresh token can be ended early. Whether a password reset ends it is the server’s decision, and products differ. Entra revokes the ones issued from the password, but not always the ones issued another way, and an explicit revoke ends them all. Neither recalls an access token already issued: unless the service enforces continuous access evaluation, it keeps working until it expires.

So find out now, while nothing is on fire, what your provider revokes on a reset and where the explicit revoke lives. Write the path down and put it in the runbook. Discovering that it is three menus deep is a bad thing to do at two in the morning.

CHECK YOURSELF

A proxy log exposes a user's access token. The same week, a stolen laptop backup exposes the refresh token from their mail client. Which exposure is worse, and why?

SHOW THE ANSWER

The refresh token, because it can keep minting new access tokens long after any single access token expires

Why. Both let the attacker act as the user, so the real question is for how long. An access token is short-lived and stops working on its own, usually within the hour. A refresh token exists to replace expired access tokens without a sign-in, so it turns a short window into standing access that lasts until it expires or is revoked at the authorization server. The reset answer fails twice: a reset does not recall an access token already issued, and what it does to refresh tokens depends on the provider and on how each token was issued.
