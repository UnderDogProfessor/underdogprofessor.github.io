Lockout protects the password, not the account

An account lockout threshold counts failures per account, which is the one axis a password spray is built to avoid.

An account lockout threshold counts failed attempts against one account. Five wrong passwords on Alice’s account and Alice is locked out.

Password spraying is built around that counter. One password, tried against every account in the directory. Alice collects a single failure. So does everybody else. Nobody approaches the threshold, nobody locks out, and the attacker comes back tomorrow with the next password.

The control is working exactly as designed. It is defending the wrong axis.

The telemetry shape is the giveaway, and it is worth knowing by heart. A brute force attack is many failures against one account. A spray is one or two failures against very many accounts, usually inside a short window, often from one source, and frequently paced to sit just inside the lockout observation window so the counters reset before anything accumulates.

Which means the detection cannot be a per-account threshold. It has to count distinct accounts that failed against a single source, or within a single time bucket, and alert on the breadth rather than the depth.

Go and read your authentication alerting. Check whether the rules group by username. If every one of them starts that way, you can see brute force and you are blind to a spray.

CHECK YOURSELF

Your SIEM alerts when an account records five failed logons in ten minutes. An attacker tries one common password against all three thousand accounts in the directory over an hour. What happens?

SHOW THE ANSWER

No alert fires, because no single account ever reaches five failures

Why. The rule groups by account before it counts, so three thousand accounts with one failure each are three thousand counts of one. Nothing crosses five and nothing fires. There is no cumulative domain-wide count unless somebody wrote one, and that is exactly the rule that is missing here. Non-existent accounts do return a distinguishable result in some logs, which is useful for spotting enumeration, but it is not what this particular threshold is measuring. The fix is a rule that counts distinct accounts per source rather than failures per account.
