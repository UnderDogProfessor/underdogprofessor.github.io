What makes a passkey phishing resistant

A passkey is bound to the origin that created it, so a lookalike domain is offered nothing at all. That binding is the whole of its phishing resistance.

A one-time code can be read aloud. A push notification can be approved by a tired person at the wrong moment. Both can be collected by a convincing page and spent somewhere else inside a minute, which is why so much phishing now succeeds against accounts that have multifactor switched on.

A passkey cannot be handed over, and the reason is narrower than people assume.

When the credential is created it is tied to the origin that created it: the scheme, the host and the port of the real site. The browser enforces that binding. Ask for a credential from a domain one character different and the browser offers nothing, because as far as it is concerned no credential exists for that site.

So the lookalike page receives nothing. Not a weak signature, not a code worth relaying. There is nothing to forward, because the assertion an attacker would need was never produced.

That is a property of the protocol rather than of the user’s attention. They do not have to notice the domain. The browser already did.

Which is also the limit worth carrying. The resistance comes from the origin check, so anything that routes around it gives the ground back.

Go and check what your sign-in page offers a user when their passkey is unavailable. That path is your real floor.

CHECK YOURSELF

A user with a passkey lands on a pixel-perfect copy of your sign-in page, hosted at a domain one character different from yours. What happens?

SHOW THE ANSWER

The browser does not offer the passkey, because the credential is bound to the origin that created it

Why. The credential is scoped to the origin it was registered against, and the browser enforces that scope before anything is signed. On a different domain there is no credential to offer, so nothing is produced and nothing can be relayed. That is why the protection does not rest on the user noticing the address, which is the step every other factor depends on. It also marks the limit: resistance comes from the origin check, so a fallback to a code when the passkey is unavailable puts the original risk straight back.
