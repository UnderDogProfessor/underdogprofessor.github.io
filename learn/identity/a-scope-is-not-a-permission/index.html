A scope is not a permission

Scope limits what an application may ask for on your behalf. It does not grant anything you do not already have, and the resource still decides.

A scope looks like a permission and is not one. It is a ceiling on what an application may attempt while acting for you, and it never raises the floor.

Two checks happen when a delegated token reaches a resource. The scope says what the application asked to be allowed to do. The user’s own authorization says what that person is allowed to do. The call succeeds only where those overlap.

So an application holding a frightening-looking scope, on behalf of a user with no special rights, reaches exactly what that user reaches. The scope string in the token is not a grant of power. It is a limit on borrowed power.

Reverse it and the shape changes entirely. Application permissions have no user in the call, which means no second check. The scope is the whole of the authorization, and the application acts as itself against every object the permission covers. That is why those need administrator consent and why they are the ones worth auditing.

The practical read on any consent screen is one question. Is this delegated or application? Delegated is bounded by the person. Application is bounded by nothing except the scope you are being asked to approve.

CHECK YOURSELF

An application requests the scope Mail.ReadWrite.All and a user with no administrative rights consents. What can the application do with that user's token?

SHOW THE ANSWER

Only what that user could already do, because the resource applies the user's own rights as well

Why. On a delegated token the resource evaluates two things: the scope, which caps what the app may attempt, and the signed-in user's own authorization, which caps what is actually permitted. The intersection wins, so a broad scope held by an ordinary user does not become administrative access. The answer changes completely for application permissions, where there is no user in the call and the scope is the only limit, which is why those require administrator consent and deserve far more scrutiny.
