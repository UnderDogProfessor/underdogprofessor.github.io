COLD CHAIN Lab 3: tracing a new admin account in the Windows Security log

A beginner lab where you create a lookalike admin account, then trace who made it and when from the Windows Security log. My log was missing the one sign-in I needed to finish the trail.

Level
1, Basics
Time
About 45 minutes
Lab computer
Windows 11 Enterprise Evaluation, build 26100, in VMware Workstation
Evidence
Security log, events 4720, 4732 and 4726

What this is

This is the third lab in COLD CHAIN, a set of hands-on incident response labs I’m building in public around a made-up company, Rimeport Cold Logistics. It uses the same Windows 11 virtual machine as Lab 2.

The story: someone on the IT team spots an account on Dana’s computer that nobody remembers creating. It’s called svc-backup2, and it looks like something IT would have made. Who created it, when, and was it given admin rights?

What the lab asks

You play the intruder. From an administrator terminal you create the account and add it to the Administrators group, writing down the time of each step. Then you find both actions in the Security log, as event 4720 (account created) and event 4732 (member added to a group), and prove they are about the same account.

What I found

  • Created, then made an administrator ten seconds later. The 4720 is at 4:36:29 PM and the 4732 into Administrators is at 4:36:39 PM. Both name Dana’s session as the one that did it (Logon ID 0x76354). The account shows up in the group record as a long ID, not a name, and that ID matched the one in the creation record, which is how I knew they were the same account.
  • Windows did more than I asked. The account was added to the Users group and to a global group called None the moment it was created, so there are two 4732 records, not one. The log also shows it being enabled, changed and given a password.
  • Deleting it added records, it didn’t remove any. Nearly three hours later I deleted the account, and the log gained four more records: it left three groups, then the deletion itself. All four carry the same Logon ID as the creation, so the same sign-in session did both.
  • The sign-in I wanted wasn’t there. The lab asks which sign-in created the account. I had cleared the Security log before starting, and that erased the record of the sign-in behind it, so I could not answer.

What I missed, and what changed because of my run

I wrote one time range for three steps instead of each step’s time, and the log shows the creation and the admin add were ten seconds apart. I also left the questions in my notes unanswered, and I didn’t notice that my Screenshot 6 showed the wrong kind of record. I wrote all of it up in my notes so readers can learn from it.

The big lesson is the log I cleared. A clean view cost me the evidence the lab is about, so the lab now warns learners not to clear the log first, and says that “I can’t find it, and here is why” is a valid answer. It also now explains the two 4732 records, lists the neighboring event IDs, and asks learners to compare the delete’s Logon ID with the creation’s.

Try it

The lab is on GitHub, and so are my notes, my screenshots and my exported .evtx logs, so you can open the real records in Event Viewer. Do the lab before reading my notes. Your times will differ.
